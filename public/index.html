Quick start

              
    
                
  1. Start Ollama and make sure at least one coding model is installed.
    2. 
                
  2. Open an absolute project directory under Workspace.
    3. 
                
  3. Select an Ollama model in the top bar. A 32K context profile is a safe everyday starting point; 64K is useful for repository exploration.
    4. 
                
  4. Press Start Pi. Pi becomes the coding agent and Ollama performs model inference.
    5. 
                
  5. Describe the task in Chat. Review streamed tool calls and inspect Git status or the editor before accepting the result.
    6. 
              

              
Recommended local workflow: one task per session, targeted tests first, compact when context exceeds roughly 60–70%, and avoid dumping complete build logs into the agent.

            


            

              
Core logic: what the application is doing

              
Pi Ollama Studio is a visual orchestration layer. It does not replace Pi’s agent loop or Ollama’s inference engine.

              

                
1. YouChoose a workspace, model, settings, and task.

                →
                
2. Studio UISends commands, renders events, and manages profiles.

                →
                
3. Pi RPCPlans work, selects tools, edits files, runs commands, and stores sessions.

                →
                
4. OllamaLoads the selected model and generates each agent response.

              

              
Request lifecycle

              
    
                
  1. The UI starts pi --mode rpc inside the selected workspace.
    2. 
                
  2. Pi loads project instructions, skills, prompts, extensions, and session history.
    3. 
                
  3. Your message is sent to Pi. Pi assembles the model context and calls the Ollama-backed model registered in Pi.
    4. 
                
  4. The model may request Pi tools such as reading, editing, writing, or running shell commands.
    5. 
                
  5. Pi executes the tool, returns its result to the model, and continues until the agent settles or you abort it.
    6. 
                
  6. The UI receives streaming RPC events and renders text, thinking, tool status, context usage, retries, and extension dialogs.
    7. 
              

              
Important: Studio never pretends that a UI setting can override Ollama architecture. Per-model generation settings are stored in Ollama profiles; server-level KV and concurrency settings require an Ollama restart.

            


            

              
Pi agent controls

              

                
Start Pi
Launches a Pi RPC process rooted in the current workspace and opens or creates a session.

                
Thinking level
Asks Pi to use the selected reasoning effort when the model/provider supports it. Higher levels can improve difficult planning but increase latency and generated tokens.

                
Send
Starts a normal user turn.

                
Steer now
Injects corrective guidance while the current agent turn is still running.

                
Follow up
Queues a message to run after the current turn settles.

                
Abort
Cancels the active Pi turn. Completed tool side effects, such as already-written files, are not automatically reverted.

              

            


            

              
Ollama models and profiles

              
The model selector lists models installed in your local Ollama instance. Pulling a model downloads it; unloading releases its active runtime allocation; deleting removes its local files.

              
Profile settings

              

                
Base model
The original Ollama model from which a named profile is created.

                
Profile model name
A new local alias, such as qwen-code:64k, with persistent parameters.

                
Context window / num_ctx
Maximum tokens Ollama can retain for the current request. Larger values use more KV-cache memory and increase prompt-processing time.

                
Max output / num_predict
Maximum generated tokens in one model response. It is not the total session limit.

                
Temperature
Randomness. Coding agents usually work best around 0.1–0.3.

                
Top P and Top K
Restrict candidate tokens. Lower values are more deterministic; overly restrictive values can make responses brittle.

                
Repeat penalty
Discourages repetitive output. Excessive values may damage code consistency.

                
Thinking model
Declares that the model supports reasoning-oriented behavior in Pi.

                
Vision input
Declares that image attachments are supported. Enable only for a compatible multimodal model.

              

            


            

              
Context window, KV cache, and VRAM

              
These settings are related, but they are not the same thing.

              

                
Context windowHow many prompt/history tokens the model can attend to.

                
KV cacheRuntime memory holding attention keys and values for those tokens.

                
Model weightsThe quantized model itself, loaded into GPU and/or system RAM.

                
Max outputThe cap for newly generated tokens in one response.

              

              
Increasing context does not make the model smarter by itself. It allows more history and files to fit, but it increases prefill time and KV-cache usage. For a 24 GB GPU, 32K is a sensible default and 64K is a deliberate agent profile. Treat 128K as an experiment that may require heavier KV quantization or CPU offload.

              
KV precision

              

                
f16
Largest KV allocation and highest precision.

                
q8_0
Recommended balance for local coding; approximately half the KV memory of f16 in common configurations.

                
q4_0
Lowest KV memory, but more quality risk at long contexts.

              

              
The displayed KV figure is an estimate because exact usage depends on the model architecture, layer count, head dimensions, context, parallel slots, and Ollama implementation.

            


            

              
Token and context monitoring

              

                
Total tokens
Cumulative input and generated tokens recorded for the current Pi session.

                
Context usage
The current active prompt after Pi’s history assembly and compaction, shown against the model context window.

                
Tool calls
How many tools Pi has invoked. Tool calls themselves are small, but large tool results can quickly fill context.

                
Runtime context
The context allocation reported for the currently loaded Ollama model.

              

              
Most common token leak: large logs and repeated whole-file reads. Ask Pi to use targeted searches, line ranges, filtered test output, and git diff.

            


            

              
Sessions, trees, steering, and compaction

              

                
Session
Pi’s persistent conversation and tool history for a workspace task.

                
Session tree
Shows branches in the conversation. Forking from an earlier user entry creates an alternate path without deleting the original history.

                
Compaction
Summarizes older context while preserving recent messages. It reduces active tokens but is intentionally lossy.

                
Custom compaction instructions
Tells Pi what facts must survive, such as changed files, decisions, failing tests, and remaining tasks.

                
Auto retry
Allows Pi to retry transient model/provider failures. It does not guarantee correction of a bad implementation.

              

            


            

              
Ollama server runtime

              

                
Base URL
Address of the Ollama HTTP API, normally http://127.0.0.1:11434.

                
Flash Attention
Enables Ollama’s optimized attention path where supported. It is normally desirable for long-context local inference.

                
Default context
Fallback server context. A named model profile can define its own context value.

                
Parallel slots
Concurrent sequences per loaded model. More parallelism multiplies KV-cache pressure; use 1 for a single local coding agent.

                
Max loaded models
How many models Ollama may keep resident simultaneously.

                
Max queue
How many requests may wait when runtime capacity is busy.

                
Keep alive
How long an idle model remains loaded, for example 10m. Longer values reduce reload latency but reserve memory.

                
Managed Ollama process
Auto-starts Ollama with the configured environment on the next Studio launch when no Ollama server is already online. Studio can only apply server-wide settings to a process it launches or to an externally configured service.

              

            


            

              
Tools, shell commands, skills, and extensions

              
Pi owns the tool loop. Studio displays tool-call arguments, progress, results, and errors. Direct shell runs through Pi rather than an unrelated terminal process, so it stays associated with the current agent workspace.

              

                
Commands, skills, prompts
Loads commands known to the running Pi process and inserts a selected command into Chat.

                
Raw Pi RPC
An advanced escape hatch for documented Pi RPC commands that do not yet have a dedicated visual control.

                
Extension dialogs
Pi extensions can request confirmation, selection, text, or editor input. Studio renders the standard RPC dialog types.

              

            


            

              
Workspace safety and review

              
    
                
  • Open only the project directory Pi should be allowed to inspect and modify.
    • 
                
  • Use Git and commit or stash important work before autonomous changes.
    • 
                
  • Review tool calls and git diff; aborting does not undo commands already executed.
    • 
                
  • Project resources may contain instructions. Disable project trust when opening an unknown repository.
    • 
                
  • The built-in editor prevents path traversal outside the selected workspace, but Pi shell tools still operate with the permissions of your local user account.
    • 
              

            


            

              
Troubleshooting

              

                
Pi does not start
Check the Pi installation path under Advanced, verify Node.js, and inspect Logs for stderr.

                
Model is missing
Refresh Ollama, pull the exact registry model name, then synchronize models to Pi.

                
Context setting appears unchanged
Use the generated model profile and start a new model load. Existing loaded instances may retain the old allocation until unloaded.

                
KV setting appears unchanged
KV type is server-wide. Stop external Ollama and restart a managed process, or configure the Ollama service environment manually.

                
Generation is very slow
Check GPU offload, lower context, use one parallel slot, unload other models, and inspect whether the model exceeds GPU memory.

                
Session becomes confused
Compact with explicit preservation instructions or start a fresh task session.
